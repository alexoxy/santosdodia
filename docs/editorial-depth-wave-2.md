# SantosDia — Editorial Depth Wave 2

Updated: 2026-08-30

## Purpose

This bounded wave continues the AdSense low-value-content remediation by increasing first-party editorial depth on existing saint profiles without expanding the indexable URL inventory merely for scale.

The chronology, Today experience, Calendar, Search, Calculator, ICS/webcal, APIs and other initial product tools remain intact. Product availability, search indexability and future monetization remain separate decisions.

## Selected identities

- Andrew the Apostle (`andrew-apostle`)
- James the Greater (`james-greater`)
- Mark the Evangelist (`mark-evangelist`)
- Luke the Evangelist (`luke-evangelist`)
- Stephen the First Martyr (`stephen-first-martyr`)
- George (`george`)

## Editorial method

Each extension is SantosDia-authored synthesis over the reviewed biography evidence and canonical relationships already attached to the identity. The wave prioritizes explanatory value rather than word count:

- separate Person from Observance and Occurrence;
- distinguish biblical or early textual evidence from later devotional memory;
- distinguish traditional textual attribution from a calendar claim;
- identify legendary material as legendary rather than converting popularity into historical proof;
- keep Church, jurisdiction and calendar-system differences explicit;
- preserve the existing source list and provenance instead of importing third-party prose.

## Publication safety

- no new saint identity is created;
- no new URL is made indexable merely because this content exists;
- no D1 write is required;
- no external prose is copied, translated or lightly paraphrased into the corpus;
- each public profile still passes the existing biography publication gate;
- the stronger editorial-depth target remains an internal quality measure, not a Google word-count requirement.

## Measurement

The repository audit now reads bounded editorial-depth files as separate waves and rejects duplicate extension IDs across them. The target for this wave is to move the current corpus from 14/29 deep-ready profiles toward 20/29 while keeping all 29 profiles above the existing baseline.
